Triagem de incidentes com IA.

O JEV lê logs de falhas de CI/CD e encaminha cada incidente para o time mais adequado, junto com o runbook recomendado para a investigação.

Como funciona

01
Recebe o log
02
Consulta o JEV
03
Classifica o incidente
04
Registra o resultado

O que é classificado

A decisão identifica o time responsável — DevOps, QA, Security, Arquitetura ou SRE — e associa um runbook operacional à falha encontrada. O resultado também registra tempo, custo e a resposta original do modelo.

Arquitetura

Uma aplicação Spring Boot recebe os logs via API e consulta o modelo typesafe/jev-1.13 pela Decisions API do OpenRouter. Lotes assíncronos são divididos em requisições de até dois logs, executadas com virtual threads e limite de concorrência. O histórico é persistido em PostgreSQL.

Endpoints principais

POST
/api/triage

Classifica um log individual.

POST
/api/triage-batch

Classifica uma lista de logs de forma síncrona.

POST
/api/triage/ingest

Recebe um lote e retorna um identificador para acompanhamento assíncrono.

GET
/api/triage/ingest/{executionId}

Consulta o progresso de um lote assíncrono.

GET
/api/history

Consulta execuções e resultados persistidos.

Exemplo de requisição

curl -X POST https://tiveumaideia.dev/api/triage \
  -H "Content-Type: application/json" \
  -d '{"log":"[error] deployment exceeded progress deadline"}'
